# Parivar Mitra V5.19.0 — Android Customer App V1

## Product goal

A native Flutter Customer app connected to the existing Parivar Mitra PHP/MySQL platform through a dedicated `/api/v2` Customer API. The app is not a WebView and does not contain database credentials.

## Android V1 capabilities

- Email-only OTP Customer authentication
- Brand-new Customer email verification + minimum profile completion
- Secure short-lived access token + rotating refresh token
- Server-side session revocation/logout
- English / Hindi / Marathi interface dictionaries
- Localized common authentication/error/status messages
- Customer Home / Family Command Center
- AI Family Assistant
- Voice input foundation using speech-to-text (EN/HI/MR locales)
- Services catalogue and starting-price display
- Customer service-request submission into existing Admin review workflow
- My Services filters and request details
- Live service-status timeline
- Book Again draft retrieval
- Family 360: family members + Pune property profiles
- In-app notifications + mark-all-read
- Invoice/payment history (read-only in V1)
- Monthly NRI/Family Summary
- Profile, language selection and logout
- Senior Easy Mode with persistent larger text scaling
- Bottom navigation: Home | AI | Book | Services | More

## Backend/API changes

- Added `/api/v2` stateless Customer API
- Added `mobile_api_sessions` for revocable app sessions
- Added `mobile_push_tokens` as FCM groundwork
- Mobile Customer auth is isolated from browser-session auth
- Admin/Super Admin/Partner/Coordinator roles cannot use Customer mobile bearer sessions
- All request/family/payment reads are customer-scoped

## Existing web platform preservation

Compared with the delivered V5.18.1 baseline, the following remain unchanged:

- Admin routes
- Customer web routes
- Partner routes
- Public routes
- Admin SEO controller
- `bootstrap.php`
- `robots.txt`
- `sitemap.xml`
- `.htaccess`

Only `includes/routes_api.php` and `VERSION.txt` are modified existing files; the mobile API and migration are additive.

## V1 payment decision

Native Razorpay checkout is intentionally not duplicated in Android V1. A mobile request enters the existing Admin-reviewed workflow and receives a server-side price estimate. Invoice/payment history is visible in the app. Native gateway checkout should be added only after Android-device payment testing and webhook regression are available.

## V1 push decision

The database groundwork for FCM tokens is included, but FCM delivery is intentionally deferred until Firebase project credentials, Android signing and real-device notification tests are available.

## Required deployment order

1. Back up current database and V5.18.1 website.
2. Import `ParivarMitra_V5.19_ANDROID_APP_V1_UPGRADE.sql`.
3. Upload the V5.19 API upgrade patch.
4. Confirm `GET https://parivarmitra.com/api/v2/bootstrap` returns JSON with `ok: true`.
5. Test Customer email OTP using a real Customer email.
6. Build the Flutter source in a Flutter/Android SDK environment or use the included GitHub Actions workflow.
7. Run `flutter analyze`, `flutter test`, and `flutter build apk --release`.
8. Perform real-device QA before any public Play Store release.

## Build-environment limitation

The development environment used to create this release has PHP but does not have Flutter/Android SDK installed. PHP and source-level Dart/security/regression checks were run here, but no APK/AAB is claimed as compiled or device-tested.
